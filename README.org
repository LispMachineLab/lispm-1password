#+title: LispM 1Password

#+HTML: <p align="center"><a href="https://github.com/LispMachineLab/lispm-1password/actions/workflows/test.yml"><img src="https://github.com/LispMachineLab/lispm-1password/actions/workflows/test.yml/badge.svg" alt="test" /></a></p>

The vaults of [[https://1password.com][1Password]] in Emacs, through ~op~, 1Password's command-line tool: the items listed
and searched, an item's fields shown, usernames, passwords and one-time codes copied.  It is an
application of [[https://github.com/LispMachineLab/lispm-desktop][LispM Desktop]], which its App Store installs, and works in any Emacs 30.1 or later.
In code, the prefix is ~lispm-1password-~.

1Password is AgileBits's.  This application is not made nor endorsed by them: it runs their ~op~,
as a terminal would.

* What it needs

- *op*, 1Password's command-line tool: =brew install --cask 1password-cli= on macOS, or as
  [[https://developer.1password.com/docs/cli/get-started/][1Password's guide]] says.  In LispM Desktop, the App Store installs it with the application;
  while it is missing, the window says so, with the command.
- *An account op knows.*  With the 1Password app, open Settings, then Developer, and turn on
  /Integrate with 1Password CLI/: op then asks the app to unlock, with Touch ID or the app's
  password, and knows its accounts.  Without the app, add the account in a terminal with
  =op account add=; unlocking then asks its password, in the minibuffer, and hands it to op.

* Using it

=M-x lispm-1password= opens its window: the items of the vaults, one a line, by title.

| =RET=   | open the item: its fields, websites, notes and tags        |
| =s= =/= | search, the list narrowing as the words are typed           |
| =v= =k= | show one vault, one kind of item                            |
| =*=     | show the favorites only                                     |
| =a=     | show all the items again                                    |
| =u=     | copy the username                                           |
| =c=     | copy the password                                           |
| =t=     | copy the one-time code                                      |
| =w=     | open the website                                            |
| =o=     | open the item in the 1Password app                          |
| =f=     | make the item a favorite, or no longer                      |
| =d=     | move the item to the Archive                                |
| =+=     | a new login, its password generated by op and copied        |
| =g=     | read the vaults again                                       |
| =L=     | lock: op signs out, and the items read are forgotten        |

An item's window has the same keys; there =RET= copies the field on its line, =r= shows its
secret, =n= and =p= go from field to field, and =q= goes back to the list.

In LispM Desktop, the App Store's 1Password opens in a window of its own, with buttons for its
main commands, the vault and kind shown under them, and a page saying what to do while op is
missing or 1Password is locked.  The desktop dresses it from its own side, with what 1Password
says of itself: ~lispm-1password-ready-p~, ~-item-p~, ~-whole-p~ and ~-revealed-p~ for the
buttons, ~-filter-label~, ~-status~ and ~-item-status~ for what the window says, ~-page-p~,
~-page-text~ and ~-page-buttons~ for its page.  1Password knows nothing of the desktop.

* Secrets

- *Read only when used.*  What op says of an item is kept without its secrets: passwords and
  other concealed fields, one-time passwords, card numbers and SSH keys.  A secret is read from op
  when it is copied or shown, by ~op read~, and blanked out once handed on.
- *Copied, then cleared.*  A secret copied leaves the clipboard after 90 seconds, and when Emacs
  quits, unless something else was copied meanwhile (~lispm-1password-clear-seconds~).  It goes
  to the system's clipboard, not to Emacs's kill ring.
- *Shown, then concealed.*  A secret shown is concealed again after 30 seconds, or when its window
  goes back to the list (~lispm-1password-reveal-seconds~).
- *Never on a command line.*  A new login's password goes to op on its standard input, in an item
  template, where no other program sees it.
- *Nothing on disk.*  The items read, their titles and usernames, stay in Emacs's memory until
  1Password is locked or Emacs quits.

* Tests

=make test compile= runs the tests and byte-compiles the files, warnings as errors.  The tests
run [[file:test/fake-op][test/fake-op]] in place of op, which answers as op does from two vaults of its own: no vault is
read, and nothing signed in to.  A test checks that no file of 1Password but the tests names
LispM Desktop's code.
